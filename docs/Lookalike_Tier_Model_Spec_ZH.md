## 1. v1.2 清单的三个变化及其建模影响

### 1.1 核心特征 71 → 69，A 组由 8 个减为 6 个

删除 `residence_region_gdp`、`region_default_rate`、`residence_price_tier` 三个地区派生变量，新增 `region`（客户当前城市，CAT）。

影响：地区信息从"三个可直接入模的数值"变成"一个高基数类别"。数值型地区变量天然带序（GDP 高低），类别型需要编码，且直接入模会放大地域偏差风险。处理方案见第 7 节。

### 1.2 30 个现金流特征改为两产品共用的备选

v1.2 明确："仅当基于 69 个核心特征的模型效果不足时才考虑"。这句话需要量化，否则永远无法判断该不该启动这批高成本特征（依赖交易明细与交易对手字段）。触发条件与验收增量见 4.6。

### 1.3 11 个产品持有字段已确认可交付

```
investment_product_flag, loan_flag, casa_flag, term_deposit_flag,
certificate_of_deposit_cds_flag, vietqr_customer_flag, vietqr_merchant_customer_flag,
mbal_insurance_policy_flag, credit_card_flag, total_product_count, banking_service_count
```

这是诊断里区分力最强的一组，V1 整组进模型。计数口径仍须排除目标产品自身；已持有目标产品的客户进 `excluded`。

## 3. 打分域再细分与模型路由

上游方案把打分域分成 Tier A / Tier B / Tier C / excluded。基于 v1.2 的特征可得性，Tier B 需要再拆三个子层，因为它们的特征结构完全不同：

| 子层 | 定义 | 规模估算 | 特征结构 | 路由 |
|------|------|----------|----------|------|
| B1 | 产品持有 ≤ 1 | ~29.06M | 产品标记位几乎恒定，交易/App 稀疏，CIC 可能有 | tier_b_extended |
| B2 | 产品 ≥ 2 但 AUM=0 或近 3 个月不活跃 | ~1.30M | 产品维度可用，行为维度恒零 | tier_b_extended |
| B3 | 其余条件齐备，仅年龄或存续期越界 | ~0.64M | **与 Tier A 完全相同** | tier_a_core |

**B3 路由到 Tier A 模型**是本次细化的一个关键调整：B3 被排除只是因为准入规则（年龄 18-60、存续期），不是因为缺特征。用尾部模型给它打分等于浪费了它齐备的特征。按诊断的漏斗，S3 步骤损失约 1.2% 的申请人（约 900 人/快照），这部分正样本也应回到 Tier A 的训练样本里。

校准分组用 `tier_a / b3 / b1 / b2` 四组：B3 与 Tier A 共用模型但准入不同，转化率可能存在系统性差异，分开校准即可吸收这个差异。

## 4. tier_a_core 模型规格

### 4.1 训练样本

- 正样本：Tier A + B3 在结果窗内的全部转化客户（PUL 单快照约 7.0 万）；
- 负样本：按 `产品档 × 子层` 分层，1:10 下采样；
- 单快照约 76 万行，4~6 期快照共 300~460 万行；
- 切分：OOT 留最新 1~2 期，开发期 60/20/20，按 CIF 分组。

### 4.2 特征集

| 阶段 | 特征数 | 说明 |
|------|--------|------|
| V1（D1+D2+D3） | 29 | 仅内部已确认源 + 主数据 + 产品持有 |
| V2（+D4+D5） | 61 | 加入交易、资产、App |
| V3（+D6 CIC） | 69 | 全量核心 |
| V4 | 99 | 满足 4.6 触发条件后加入 30 个现金流特征 |

11 个产品持有字段已确认可交付，V1 用整组。

### 4.3 缺失、类别与单调约束

- 数值缺失：LightGBM 原生 NaN，不做全局填充；缺失率 30%~95% 的特征加 `_is_missing` 指示位；
- 类别特征 8 个（`marital_status`、`education_level`、`occupation_type`、`region`、`balance_trend_6m`、`cic_score_trend`、`salary_trend_6m`、`app_usage_time_preference`）：LightGBM 原生 `categorical_feature`，`region` 另见第 7 节；
- 单调约束：目录中 28 个特征已标注方向（产品数、存续期、余额、代发月数、可支配收入、App 意图类为正；NPL、DTI、逾期天数/次数、他行负债收入比、距上次登录天数、收入波动为负），其余为 0。约束由 `monotone_constraints()` 按特征顺序生成。

### 4.4 参数基线

```python
params = {
    "objective": "binary", "metric": "auc",
    "learning_rate": 0.05, "num_leaves": 63, "min_data_in_leaf": 100,
    "feature_fraction": 0.8, "bagging_fraction": 0.8, "bagging_freq": 5,
    "lambda_l2": 1.0, "seed": 42,
}
```

早停在**自然占比**验证集上做；调参用 `StratifiedGroupKFold`（分组键 CIF），目标 CV-KS 或 PR-AUC。

### 4.5 校准与验收

- 分层 offset 校准（`tier_a`、`b3` 两组），拟合在自然占比验证集；
- 验收：各组 `预测率/实际率` ∈ [0.9, 1.1]；层内 Lift@20% ≥ 1.2；相对"产品持有数单特征排序"提升 ≥10%；OOT 与开发期的 KS 差距在可解释范围内。

### 4.6 30 个可选现金流特征的启用条件

同时满足以下两条才启动数据开发：

1. V3（69 特征）模型在 OOT 上层内 Lift@20% < 1.5，或 KS 低于同期 LR+WOE 基线 0.02 以内（说明核心特征已到瓶颈）；
2. 目标客群的结算账户流水覆盖率 ≥ 60%（低于此值时该组特征主要是缺失指示位）。

纳入门槛：在 OOT 上带来 KS 提升 ≥ 0.02 或 Lift@20% 相对提升 ≥ 5%，否则不纳入生产模型——这 30 个特征依赖交易明细与交易对手字段，取数与维护成本远高于核心特征。

## 5. tier_b_extended 模型规格

### 5.1 训练样本：用尾部自身样本，而不是全域加权样本

核心池正样本约 69,130，尾部约 7,681（由 90% 留存反推），大约 9:1，且核心池样本权重为 1。把两层混进同一个加权训练集，梯度仍会被核心池主导，尾部自己的模式学不出来。

因此尾部模型只用尾部人群自己的分层抽样样本训练，通过校准层与 Tier A 对齐刻度，不共享训练样本。要不要拆模型，等 MB 快照按第 8 节对照后再定。

### 5.2 特征集

规划 **26** 个（第 2 节，默认无 CIC），实证筛选后再定。删除的是 D/E/G 组、App 深度类、以及尾部覆盖不足的 CIC。

### 5.3 建议向 MB 追加的尾部专用特征

v1.2 的 69 个特征是围绕"有关系深度的客户"设计的，对单产品/休眠客户区分度有限。以下 7 个字段取数成本低，且直接刻画尾部客户的差异，建议加入清单：

| 建议特征 | 业务含义 | 为什么对尾部有用 |
|----------|----------|------------------|
| `single_product_type` | 唯一持有产品的类型（CASA/卡/存款/贷款） | B1 内部最主要的结构差异 |
| `account_dormancy_months` | 距最近一次余额变动或交易的月数 | 区分"休眠很久"与"刚沉寂" |
| `salary_credit_ever_flag` | 历史上是否有过代发记录 | 代发关系是尾部转化的强前提 |
| `has_cic_record_flag` | 是否存在 CIC 记录 | 缺失即信息，且决定 C 组特征是否可用 |
| `account_open_channel` | 开户渠道（网点/eKYC/数字） | 数字开户客户更易被数字渠道触达 |
| `has_txn_history_flag` | 观察窗内是否有任何流水 | D/E 组特征的可得性标记 |
| `mb_app_installed_flag` | 是否安装过 App（区别于是否活跃） | 决定 App 触达是否可行 |

### 5.4 参数基线（与 Tier A 的差异都有原因）

```python
params = {
    "objective": "binary", "metric": "auc",
    "learning_rate": 0.03, "num_leaves": 31, "min_data_in_leaf": 200,
    "min_sum_hessian_in_leaf": 50.0,      # 关键：IPW 权重下必须用加权口径约束叶子
    "lambda_l2": 10.0, "feature_fraction": 0.7, "seed": 42,
}
```

`min_data_in_leaf` 统计的是**行数**，而尾部负样本带 100~500 的 IPW 权重，少数几行就能主导一个叶子的梯度。必须同时设 `min_sum_hessian_in_leaf`（加权口径）才能真正约束叶子规模。权重建议封顶 200。

### 5.5 CIC：尾部默认不用，有记录的少数人单列

已确认 CIC 在尾部覆盖不多。因此：

| 人群 | 特征数 | 处置 |
|------|--------|------|
| 尾部默认（无 CIC 或覆盖不足） | **26** | 主路径。层内 Lift@20% < 1.2 则**停止输出模型分**，改为分层先验 |
| 尾部且有 CIC 记录 | 26+8=34 | 可加 CIC 字段，并按 `has_cic_record_flag` 分组校准；覆盖太薄时不必单训一个模型 |
| 种子池 | 69（含 8 个 CIC） | CIC 仍进核心模型 |

不要等 CIC 才启动尾部模型。尾部能不能排，看 26 个内部字段（尤其是产品持有）在 OOT 上过不过 Lift@20% ≥ 1.2。

### 5.6 验收与探索投放

- 层内 Lift@20% ≥ 1.2 且在 OOT 上保持；
- 校准后各子层 `预测率/实际率` ∈ [0.85, 1.15]（尾部正样本少，区间比 Tier A 宽）；
- 达标后也只进探索名单：按推算的 2.5/万 基线，尾部单独做 A/B 每臂需要约 172 万人，KPI 验证仍放在 Tier A。

## 6. 分层特征筛选流程

BRD 3.3 的四条阈值（缺失率 >95%、单值率 >95%、IV <0.02、P99 截断）必须**在每一层内部分别计算**。全域口径会把"Tier A 覆盖 95%、Tier B 覆盖 8%"的特征判为可用，然后在尾部模型里塞进一列几乎全空的数据。

### 6.1 稀疏层的两个 IV 陷阱（公式问题）

这两条来自 WOE/IV 定义和正样本稀疏时的抽样波动，**不是**从 MB 宽表或仓库样例 CSV 上测出来的。2.5/万只提供了"尾部有多稀"的量级。

**陷阱 1：空正样本分箱让 WOE 取到 ±∞，未平滑 IV 被分箱个数撑爆。**

WOE / IV 定义：

```
WOE_i = ln( (n_{i,1} / N_1) / (n_{i,0} / N_0) )
IV    = Σ_i (n_{i,1}/N_1 − n_{i,0}/N_0) · WOE_i
```

某个分箱 `n_{i,1}=0` 时，`ln(0) → −∞`。工程上常用 `+1e-10` 代替 0，于是 WOE 变成大约 `ln(1e-10 / 负样本占比) ≈ −20`，空箱的 IV 贡献 ≈ `负样本占比 × 20`，**与特征有没有信息无关**。

手算例子（10,000 行、3 个正样本 = 3/万，四个等频类别箱，3 个正样本全在 A；实现见 `test_empty_positive_bins_inflate_unsmoothed_iv`）：

| 箱 | 行数 | 正样本 | 未平滑 WOE（ε=1e-10） | 未平滑 IV 贡献 |
|----|------|--------|----------------------|----------------|
| A | 2,500 | 3 | +1.39 | 1.04 |
| B/C/D 各 | 2,500 | **0** | −21.64 | **各 5.41** |
| 合计 | 10,000 | 3 | — | **IV ≈ 17.3** |

三个空箱就贡献了 16.2。转化率 2.5/万 时，月份、城市、产品档这类类别特征很容易出现"整箱没有正样本"，所以未平滑 IV 到 4、到 17 都只说明分箱空了，不说明特征强。处理：分箱计数做 Laplace 平滑（α=0.5），`smoothed_iv()`；上例平滑后 IV ≈ 0.88。

**陷阱 2：正样本只有几百个时，噪声也能跨过 IV≥0.02。**

BRD 的 0.02 门槛默认正样本充足。正样本少、分箱多时，随机波动就会把 IV 抬过线。单测夹具（1,197 行、**234 个正样本**、纯 `N(0,1)` 噪声、seed=14）上 `smoothed_iv ≈ 0.038`，已经高于 0.02；同样规模下约 90% 的随机种子都会超线。这 234 是夹具里写死的正样本数，与 2.5/万、与 4.72M 种子池都无关。

处理：设正样本下限（建议 ≥500，代码默认 200）——低于下限时 IV 只报告不做剔除；同时要求**跨 cohort 的最小 IV** 达标。

### 6.2 Tier A 建议放宽 IV 门槛

LightGBM 对弱特征不敏感，在正样本充足的 Tier A 上把 IV≥0.02 当硬门槛，容易砍掉只有交互价值的变量。建议：

- Tier A：只用缺失率与单值率做硬剔除，IV 降为排序参考（或阈值放宽到 0.01）；
- Tier B：保留 IV 门槛（配合平滑 + 正样本下限 + 跨 cohort 稳定性），因为尾部样本稀疏，噪声特征代价更高；
- LR+WOE 轨道：两层都保留 IV≥0.02 的传统口径，用于监管留档。

## 7. region 高基数与公平性

`region` 为城市级类别，越南 63 个省市，尾部客群的地区分布还与核心池不同。

- **LightGBM 轨道**：原生 `categorical_feature`，并设 `min_data_per_group`（建议 200）与 `cat_smooth`（建议 10~30），防止小城市过拟合；
- **LR+WOE 轨道**：WOE 编码，样本不足的城市合并进"其他"；
- **不推荐**直接用无交叉验证的目标编码，会把标签泄漏进特征；若要用，必须 K 折 out-of-fold 编码；
- **公平性**：BRD 4.2 要求按地区比较响应率，差异 >20% 触发复核。`region` 直接入模会放大地域偏差，建议同时准备 `city_tier`（城市分档）版本，若公平性检查不通过则降级到分档版本；
- v1.2 删掉的 `residence_region_gdp` / `region_default_rate` / `residence_price_tier` 本质是 region 的数值化编码。若后续重新获批外部数据，它们比高基数类别更稳定，值得重新纳入。

| 对照 | 目的 | 通过标准 |

| 分层计算缺失率 / 单值率 / 平滑 IV | 确认两层筛出的特征集不同 | 记录每层保留清单，禁止用全域 IV 代替 |
| 尾部模型：仅尾部样本 vs 混入核心池 | 确认混训是否损害尾部排序 | 层内 Lift@20% 不低于混训 |
| 相对产品数单特征排序 | 确认模型不是复述筛选规则 | 层内 Lift@20% ≥ 1.2，且相对该基线有增量 |
| 尾部默认 26 特征（无 CIC） | 确认尾部能否打模型分 | 层内 Lift@20% < 1.2 则只输出分层先验 |
